# pr/ — forwardable framework requests

Every gap in the **abap2UI5 framework** that porting a UI5 demo kit sample
reveals is written up here as a ready-to-forward request — **one folder per
request, one README.md each**, self-contained (motivation, current behavior
with source references, proposed change, example) so it can be pasted
directly into an issue/PR at
[abap2UI5/abap2UI5](https://github.com/abap2UI5/abap2UI5).

**This is a pure backlog folder: it holds OPEN requests only.** A request whose
change is live (merged upstream, or landed in this repo's tooling) has its
folder **deleted** in that same change — the details then live upstream, in
`CAPABILITIES.md` and in `STATUS.md`; only a one-line row in the "Implemented"
table below stays behind as the pointer. So every folder present here is work
still to be done — nothing in it is already shipped.

Convention (see AGENTS.md §10 / TRAINING.md "Distill"): whenever porting or
reviewing surfaces an improvement idea for the framework — a missing API
parameter, a capability marked ❌ in CAPABILITIES.md that upstream could
close, a behavior gap — add or extend a request folder here **in the same
change**.

## Open

Genuinely open — not yet implemented.

The six abap2UI5 requests below came out of the **IMPROVISED harvest**
(2026-08-05): every `IMPROVISED` deviation in `meta/` classified into gap ·
probe · rework · boundary · policy, repeatably, by
`node scripts/probes/improvised-cluster.mjs`. Each row names the family key to
re-read its evidence (`--family <key>`).

| Request | Summary | Priority |
|---------|---------|----------|
| [`model-empty-vs-default`](model-empty-vs-default/) | **An initial ABAP field cannot stay ABSENT from the model.** `main_json_stringify` serializes with `iv_ignore_empty = abap_false`, so `''` reaches the client as an explicit value: an enum property gets `""` (rejected), a control default is silently overridden, and a bound template whose rows set different property subsets cannot be used at all — app 049 unrolled the sample's bound List into static items for exactly this. Asked for: a per-bind `omit_initial` opt-in (the `custom_filter` slot + `create_empty_filter( )` plumbing already exists) plus path scoping. Family `empty-vs-default`, apps 010/012/018/049/289 | high — the only IMPROVISED gap that forces a *structural* deviation |
| [`control-inline-style`](control-inline-style/) | **A CSS value cannot be set on a control that has no matching property.** Three samples resize a `sap.m.Page` container via `byId(…).$().width(v + '%')` — `sap.m.Page` has no `width`, so neither the two-way-bound-property path nor a control method applies and the Sliders sit inert. `addStyleClass` carries a class name but no value. Asked for: `css: ["string","string"]` writing `property/value` to the control's own DOM ref. Family `dom-style`, apps 138/250/267/269 | medium — 4 ports, each visibly dead in the running app |
| [`table-set-sticky`](table-set-sticky/) | **`sap.m.Table.setSticky` needs the `object` arg kind.** The generalized allowlist reaches the method but infers a *string* argument, so the array never arrives. App 009 mirrors the array server-side (one round-trip per click); apps 022/235 deleted the feature's Label + three CheckBoxes from the view. One line, exactly the shipped `setHiddenInPopin: ["object"]` shape. Family `array-property`, apps 009/022/235 | medium — one line upstream, undoes one improvisation and two structural drops |
| [`control-method-null-arg`](control-method-null-arg/) | **A control method cannot be called with null.** An association (`setSelectedSection`) is not bindable, so a method call is the only path — but an empty argument is inferred as `false` (`castArgAuto`), never `null`. The concept already ships for exactly one kind (`within`, from `pr/popup-within-area`); asked for: a general `controlIdOrNull` kind. Family `null-argument`, app 263 | low — 1 port, but latent in every association setter |
| [`invisible-message-announce`](invisible-message-announce/) | **No ARIA live announcement.** `sap.ui.core.InvisibleMessage` is a singleton — no id for `CONTROL_BY_ID`, no entry in `GLOBAL_TARGETS` — so a backend-driven content change cannot be announced to a screen reader at all. Asked for: an `INVISIBLE_MESSAGE` global target with `announce: ["string","string"]`, resolved lazily like `THEMING` (@since 1.78). Family `a11y-announce`, app 289 | medium — an accessibility hole for every abap2UI5 app, not just this port |
| [`custom-currency-formatting`](custom-currency-formatting/) | **`Formatting.setCustomCurrencies` is unreachable.** No `FORMATTING` entry in `GLOBAL_TARGETS`, and a currency's digit count is neither a control property nor something the curated formatter can register for the standard `sap.ui.model.type.Currency`. Affects any app with a non-standard `CURRDEC`, not only the sample. Family `formatting-config`, app 196 | low — narrow, but nothing else can express it |
| [`open-abap-xml-escaping`](open-abap-xml-escaping/) | **Upstream target is [open-abap/open-abap-core](https://github.com/open-abap/open-abap-core), not abap2UI5.** `CALL TRANSFORMATION id … RESULT XML` writes element character data unescaped, so an app whose model carries a `<` (the overview's generation notes) saves a draft that `CL_IXML` cannot parse back — the next round-trip dies in an uncatchable `ASSERT` and the frontend shows `Network error: ASSERTION_FAILED`. Worked around here by a build-time patch (`web/ci/patch_open_abap_xml.mjs`) applied by both transpiled builds; delete this folder when the fix is upstream. | high — breaks every round-trip of the Pages demo's front door |

_`menu-item-selected-path` left this list on 2026-07-31: it was closed by
**option 2** of its own proposal — a documented capability boundary, measured
rather than assumed, with the "an event arg is a full UI5 expression"
capability as the by-product (see the Implemented table)._

## Declined / deferred (folders removed)

| Request | Decision |
|---------|----------|
| urlhelper-abap-api | **Withdrawn 2026-07-22 — the premise was wrong.** The `URLHELPER` frontend action *is* callable from ABAP: `cs_event-urlhelper` with `TRIGGER_TEL`/`TRIGGER_SMS` (number as a plain string param) and `TRIGGER_EMAIL`/`REDIRECT` (a `{ EMAIL/URL, … }` object-literal `t_arg` — `get_t_arg` emits `{`-prefixed args raw as UI5 event-handler object literals). App 084 ported 1:1 this way; apps 041/073's external links switched from the (same-origin-only) `open_new_tab` to `urlhelper` REDIRECT. Captured as a CAPABILITIES.md convention instead of a framework change |
| named-json-models | **Too complicated with the current abap2UI5 approach** — every view slot serializes exactly one ABAP-fed default JSONModel per roundtrip; a second named model would have to be carried through bind, serialization and model-update on every slot. Declined for now, possibly worth re-discussing in the future if the model layer changes. Workaround stays: flatten into the default model or resolve statically (IMPROVISED deviation, apps 006/031/046, same family app 044) |
| message-manager-binding | **Half already covered, half implemented** — first recorded (b07) as "not filed, already covered": reading messages IS covered by the `message>` auto-collection (2026-07-18) and the plain-table MessagePopover (app 038). But porting `MessagePopoverMessageHandling` (b08) showed the **write** half — the controller's `MessageManager.addMessages` with custom text/target — was not expressible. Implemented 2026-07-20 as the `z2ui5.cc.MessageManager` companion control (see Implemented table) |
